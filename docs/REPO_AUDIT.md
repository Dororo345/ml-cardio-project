## Расхождения с проектной документацией

1. ЛЗ 4 планирует MVP к W15; сценарные 9 недель закрытия историй в ЛЗ 6
   не являются реальным подтверждением факта выполнения.
2. `CARD-07` описывает 422 при ошибочном вводе, а имеющийся API возвращает
   HTTP 400. Также в критериях упоминается версия модели; в ответе
   текущего API такой версии нет. Нужна согласованная редакция контракта.
3. `CARD-12` подразумевает 50 тестовых примеров, включая отрицательные,
   и end-to-end проверку очистки формы. Набор текущих тестов включает
   50 позитивных API-запросов и отдельные отрицательные, но не заменяет
   полноценный браузерный протокол UAT.
4. ADR в GitHub описывает магистерское исследование с Kanban; план ЛЗ 4–5
   использует 15-недельную контрольную сетку. Можно применять Kanban
   в рамках календарного учебного плана; обе модели не следует
   выдавать за разный фактический процесс.
5. Исходная проверка показала `debug=True`, теперь в добавленной версии
   `debug=False`, локальный bind, лимит JSON. Лимит частоты запросов,
   журнал запуска сканеров и реальная проверка совместимости ML всё ещё нужны.
6. Имеющаяся модель сохранена со sklearn 1.6.1. Зависимость закреплена
   в `requirements.txt`; фактический прогон после установки должен
   подтвердить отсутствие InconsistentVersionWarning.
7. Указанные в `data/metrics.json` значения не пересчитывались, а источник
   и лицензия датасета должны быть подтверждены отдельно.
