# ЛЗ 11 — мониторинг доступности учебного стенда

Цель: обнаруживать, когда перестала отвечать страница входа. Этот мониторинг не подтверждает правильность медицинского прогноза, CSRF или работоспособность настоящей клинической системы.

## Вариант для Linux с установленным Docker

Запустить V3 отдельно на `127.0.0.1:8000` (или через учебный контейнер с сетью host). Затем:

```bash
docker run -d --name uptime-kuma-lz11 --network host \
  -v uptime-kuma-lz11:/app/data --restart unless-stopped \
  louislam/uptime-kuma:1
```

Открыть `http://127.0.0.1:3001`. Создать **HTTP(s)** монитор с названием `CardioPrognoz V3 login`, URL `http://127.0.0.1:8000/login`, интервалом 30 секунд и ожидаемым статусом 200. Для репетиции остановить тестовый сайт, дождаться изменения статуса на Down, запустить сайт и зафиксировать возврат в Up. Записать время, скриншоты без данных пациентов и имя участника. Не использовать реальные учётные данные для монитора.

На Windows Docker Desktop сетевой адрес и подключение к хосту отличаются: обычно используют `host.docker.internal` и опубликованные порты контейнера. Не открывать диагностический интерфейс во внешнюю сеть. Команда Linux с `--network host` не является универсальной для Windows.

## Статус на 2026-11-20

В рабочей среде подготовки ЛЗ 11 Docker недоступен. Поэтому **запущенный Uptime Kuma и изменение Up/Down не подтверждены**. Монитор следует выполнить на машине с Docker, записать фактические результаты и приложить ссылку/безопасный скриншот к Issue PM-03. До этого соответствующая проверка остаётся открытой.
