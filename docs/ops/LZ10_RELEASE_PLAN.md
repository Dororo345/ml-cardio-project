# ЛЗ 10 — план релиза и отката «КардиоПрогноз»

Дата подготовки: 2026-11-16. Продукт: Flask CardioPrognoz_V3, **только учебная среда и синтетические данные**.

## Определения и окружения
- Рабочий код: `main`. Перед выпуском — PR, обязательный CI, проверка минимум одним независимым рецензентом, если доступен.
- Среда `lz10-pr-validation`: временный Docker-контейнер на runner для проверок PR, **не развёртывание в продакшн**.
- Среда `lz10-ci-staging`: временный Docker-контейнер, проверенный HTTP smoke-test после коммита в main; **не постоянный стенд**. Деплой подтверждается статусом GitHub Deployment `success`, а не просто зелёной сборкой.
- GitHub environment и deployment statuses создаются job `container-smoke`; по окончании job контейнер удаляется. Публикация приложения в Интернете не выполняется.

## Релизный план
| Шаг | Окно / ответственный | Действие / критерий |
| --- | --- | --- |
| Подготовка | За день до планового релиза, разработчик | Проверить изменения, зависимости, синтетические данные, тесты, changelog |
| Выбор окна | Предлагаемое учебное окно: вторник 11:00–12:00 по Алматы, **согласовать с заказчиком** | Не выпускать в час пик и накануне выходных |
| Согласование | Перед слиянием, ревьюер | Review PR, обязательные зелёные quality / secrets / container-smoke |
| Релиз | После слияния PR, ответственный за выпуск (назначить) | Автоматический staging smoke, зафиксировать commit SHA и ссылку Actions |
| Сообщение заказчику | В течение рабочего дня, руководитель проекта | Версия, функциональность, ограничения, ссылка на успешный job, известные проблемы |
| Проверка | Сразу после выпуска, тестировщик | Проверить HTTP /login, авторизацию, /predict и тестовый CSV без реальных пациентов |
| Измерение | Еженедельно, разработчик | DORA с периодом 30 дней, журнал инцидентов, пересмотр улучшений |

Владелец выпуска и тот, кто утверждает откат: **назначаются командой перед первым настоящим релизом**. Нельзя выдавать незаполненную роль за подтверждённое назначение.

## Чек-лист релиза
- [ ] Выбран SHA и журнал изменений; согласовано окно.
- [ ] Изменения прошли PR и независимый review.
- [ ] CI действительно зелёный; тестовое покрытие не ниже 50%.
- [ ] Gitleaks не обнаружил секреты; контейнер успешно собран.
- [ ] Нет пациентских данных в тестовой среде и артефактах.
- [ ] Сохранены предыдущий SHA/тег, параметры окружения и путь к резервной копии (если используется).
- [ ] Smoke-test /login вернул HTTP 200, зафиксирована ссылка на job.
- [ ] Заказчик уведомлён; DORA-период и определение развёртывания записаны.

## Чек-лист отката
1. **Единоличное решение:** назначенный release owner (указать ФИО до релиза); если не назначен — выпуск запрещён.
2. Триггер: smoke-test не проходит, обнаружена критическая ошибка доступа/безопасности либо нарушен контракт.
3. Остановить дальнейшие развёртывания; зафиксировать инцидент и SHA, время начала UTC.
4. Для эфемерного стенда остановить runner/container; он будет удалён автоматически по завершении job. Для постоянного стенда — переключить образ на заранее сохранённый тег/предыдущий SHA.
5. Восстановить сохранённую конфигурацию и, если применимо, совместимый бэкап БД (никогда не публиковать базу с хешами паролей).
6. Повторить smoke-test и основные сценарии; записать UTC-время восстановления и ссылку на доказательство.
7. Сообщить заказчику, создать issue и заполнить `docs/ops/INCIDENTS.csv`.

**Целевой лимит для учебного отката:** 15 минут с момента решения, подлежит проверке на реальном стенде; не выдаётся за измеренный результат. Ответственный принимает решение **не позже 5 минут** после подтверждения критического сбоя (целевое значение, не факт).
