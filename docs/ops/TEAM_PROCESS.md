# КардиоПрогноз — процесс команды и текст для GitHub Wiki (ЛЗ 10)

**Текст для страницы GitHub Wiki «Процесс команды»**. Файл в репозитории не означает, что сама Wiki изменена. Опубликовать вручную в GitHub → Wiki, если Wiki включена.

## Время жизни веток
- Одна ветка = одна задача (или отдельный небольшой PR).
- Время от создания ветки до объединения/закрытия **не больше трёх календарных дней**.
- Каждый день проверять PR и блокировки; при приближении к 3 дням — делить изменение, обсуждать блокер и приоритет с владельцем задачи.
- Формат: `feat/CARD-12-short-name`, `fix/CARD-24-short-name`, `docs/LZ10-release`.
- `main`: только PR + обязательный CI + один независимый review после фактической настройки GitHub Rulesets.
- Цель длительности LZ10 Actions — максимум 10 минут. Сбой CI не обходить прямым push.

## Определения DORA
Развёртывание — GitHub Deployment со статусом `success/failure/error` для среды `lz10-ci-staging`; обычный CI run не считается.
- Deployment Frequency — успешные deployment / количество недель.
- Lead Time — медиана времени между committer date SHA и успешным deployment status.
- Change Failure Rate — доля уникальных завершённых deployment, которые завершились failure/error **или** потребовали документированного исправления/отката за 24 часа после успешного deployment.
- Time to Restore — медиана длительности завершённых зарегистрированных инцидентов, N/A при отсутствии инцидентов.
Полная формула, ограничения, ссылки и процедура подсчёта: [docs/ops/LZ10_DORA.md](LZ10_DORA.md).

## Контроль перед публикацией
1. Преподаватель должен иметь доступ к Wiki.
2. Создать или изменить страницы «Процесс команды» и «Метрики DORA».
3. Скопировать актуальные определения без подмены неизвестных данных нулём.
4. Сохранить прямые ссылки на обе страницы и добавить их в журнал сдач.
