# ЛЗ 9: политика потока «КардиоПрогноз»

**Источник:** GitHub Issues + отдельные события переходов. Документ — настройка, а не доказательство проведённых спринтов.

| Статус | WIP | Условия входа и выхода |
|---|---:|---|
| Backlog | — | Новая задача; в Ready после проверки DoR |
| Ready | — | Критерии, зависимости и приоритет известны; в работу по свободному слоту |
| In Progress | 2 | Исполнитель начал работу; при наличии PR передать на ревью |
| Waiting Review | 2 | PR ожидает проверки; ревьюер берёт в работу |
| Review | 1 | Проверка кода или документа; замечания устранены |
| Testing | 2 | Проверка критериев; при дефекте возврат в работу |
| Done | — | Полностью выполнен DoD; GitHub Issue закрыт |

**На лимите WIP:** не брать новую задачу, помогать завершать существующие. Срочная задача — не более одной.

## Definition of Ready (DoR)
1. Описана ценность для пользователя.
2. Есть проверяемые критерии приёмки, включая негативный сценарий для ввода/API.
3. Определены зависимости, исполнитель и объём не более одной недели.
4. Используются только синтетические данные, не реальные данные пациентов.

## Definition of Done (DoD)
1. Есть ссылка на код/PR/документ и подтверждённые критерии приёмки.
2. Пройдены применимые тесты с ссылкой на CI или вывод команды.
3. Результат прошёл проверку; если разработчик один, не выдавать самопроверку за независимое ревью.
4. Документация актуализирована; отсутствуют секреты и медицинские ПДн.
5. Весь продукт маркирован как демонстрационный, не медицинский диагноз.

## Фиксация статусов
На **каждый реальный переход** добавить отдельный комментарий к Issue:
`FLOW: Ready`, `FLOW: In Progress`, `FLOW: Waiting Review`, `FLOW: Review`, `FLOW: Testing`.
Закрытие Issue после DoD означает `Done`. Дата = реальное `created_at` комментария или событие GitHub `closed`. Не создавать фиктивные события и не ставить даты задним числом. При наличии GitHub Projects **параллельно** вручную изменить колонку в тот же день.

**Метрики:** throughput = число закрытых в спринт; cycle time = первый In Progress → Done; p85 = nearest-rank; средний WIP = ежедневные снимки; CFD = динамика распределения задач по статусам. При отсутствующих событиях не подставлять придуманные значения.

Ретро проводится по реальным данным: ровно одно измеримое действие, владелец, срок и метрика успеха. Ограничения WIP — правила команды, а не доказательство автоматической блокировки GitHub Projects.
