# Статус проекта к W9 — только подтверждённые факты

## Из предыдущего архива CardioPrognoz.zip

- Есть `app.py`, Flask форма с 13 полями, модель joblib и SHAP, данные/метрики и тест `tests/test_mvp.py`.
- Был явно включён `debug=True`; в этом пакете отключён.
- Предварительная ML-оценка сохранена в `data/metrics.json`, без повторной оценки.
- Тест `tests/test_mvp.py` включает 50 синтетических POST-сценариев; наличие тестов **не является свидетельством** их прохождения на GitHub.

## План и расхождение в документации

- ЛЗ4/ЛЗ5: W1–8 = датасет + ML, W9–12 = API/UI/XAI, W13–14 = 50 тестов и НФТ, W15 = защита.
- ЛЗ6: 12 историй MVP за 9 недель — **сценарно реконструированный throughput**, не фактический журнал.
- Нельзя помечать все `CARD-01..12` как завершённые лишь на основании расчёта ЛЗ6.

## Необходимо подтвердить

1. Полученный GitHub ZIP изучен: в нём только README и три документа. Историю коммитов и состояние удалённой ветки после экспорта ZIP ещё необходимо проверить.
2. Повторный запуск всех тестов на Python 3.11 с зафиксированными зависимостями.
3. По каждому `CARD-01..12`: критерии приёмки и свидетельство (тест, скриншот, commit/PR).
4. Реальные интервью из ЛЗ4 (если нужны для сдачи), протокол ML и XAI, 50 случаев.
5. Выполнение security GitHub Actions (Gitleaks / Trivy), корректировка найденных ошибок.
6. НФТ, включая p95 и отсутствие медпоказателей в логах; отчёты не выдумывать.

## Изменения в данном пакете

- Защита `/predict` через отдельный валидатор; reject unknown, 13 numeric features; ошибки с кодом и request_id.
- Ограничение тела 16 KiB, HTTP security headers, `debug=False`, localhost.
- README, requirements.txt, GitHub Actions, файл импорта Issues и инструкции.
- Не добавлены логин, история пациентов и интеграция с МИС: это версия 2/3 и требует отдельного решения по персональным данным.
